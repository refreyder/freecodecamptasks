Клонируйте [этот репозиторий GitHub](https://github.com/freeCodeCamp/boilerplate-project-exercisetracker/) и завершите свой проект локально.
Для завершения проекта используйте любой конструктор сайтов на ваш выбор. Обязательно подключите все файлы из нашего репозитория на GitHub.
Ваши ответы должны иметь следующую структуру.

Упражнение:

```
{
  username: "fcc_test",
  description: "test",
  duration: 60,
  date: "Mon Jan 01 1990",
  _id: "5fb5853f734231456ccb3b05"
}
```

Пользователь:
```
{
  username: "fcc_test",
  _id: "5fb5853f734231456ccb3b05"
}
```

Журнал:
```
{
  username: "fcc_test",
  count: 1,
  _id: "5fb5853f734231456ccb3b05",
  log: [{
    description: "test",
    duration: 60,
    date: "Mon Jan 01 1990",
  }]
}
```

Подсказка: Для получения ожидаемого результата можно использовать метод API для данного dateсвойства .toDateStringDate



Тесты

1. Вам следует указать свой собственный проект, а не пример URL-адреса.
2. Вы можете POST использовать /api/users данные формы username для создания нового пользователя.
3. Ответ, возвращаемый POST /api/users формой с данными, username будет представлять собой объект со свойствами username и ._id
4. Вы можете отправить GETзапрос на /api/users получение списка всех пользователей.
5. GETЗапрос /api/users возвращает массив.
6. Каждый элемент массива, возвращаемого функцией, GET /api/users представляет собой литерал объекта, содержащий имя пользователя username и его идентификатор _id.
7. Вы можете POST использовать /api/users/:_id/exercises данные формы description, duration а также, при необходимости date, . Если дата не указана, будет использоваться текущая дата.
8. В ответ POST /api/users/:_id/exercises будет получен объект пользователя с добавленными полями для упражнений.
9. Вы можете отправить GETзапрос на /api/users/:_id/logs получение полного журнала тренировок любого пользователя.
10. Запрос к журналу пользователя GET /api/users/:_id/logs возвращает объект пользователя со count свойством, представляющим количество упражнений, принадлежащих этому пользователю.
11. GETЗапрос /api/users/:_id/logs вернет объект пользователя с log массивом всех добавленных упражнений.
12. Каждый элемент массива log, возвращаемый функцией, GET /api/users/:_id/logs представляет собой объект, который должен иметь свойства `a` description, ` durationb`, `b` и ` b`.date
13. descriptionСвойство любого объекта в logмассиве, возвращаемого функцией, GET /api/users/:_id/logs должно быть строкой.
14. durationСвойство любого объекта в logмассиве, возвращаемого функцией, GET /api/users/:_id/logs должно быть числом.
15. dateСвойство любого объекта в logмассиве, возвращаемого функцией, GET /api/users/:_id/logs должно быть строкой. Используйте dateStringформат API Date.
16. Вы можете добавить параметры from, to и limit к запросу GET /api/users/:_id/logs, чтобы получить часть логов любого пользователя. from и to — это даты в формате yyyy-mm-dd. limit — это целое число, указывающее, сколько логов нужно отправить обратно.
