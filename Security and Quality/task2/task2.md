Тесты:
Ожидание :1. Вы можете указать свой собственный проект, а не пример URL-адреса.
Ожидание :2. Вы можете отправить POSTзапрос /api/issues/{projectname}с данными формы, содержащими обязательные поля issue_title, issue_text, created_by, и, при необходимости assigned_to, и status_text.
Ожидание :3. Запрос POSTвернет /api/issues/{projectname}созданный объект и должен включать все отправленные поля. Исключенные необязательные поля будут возвращены в виде пустых строк. Кроме того, включите created_on(дата/время), updated_on(дата/время), open(логическое значение, trueдля открытого состояния - значение по умолчанию, falseдля закрытого состояния) и _id.
Ожидание :4. Если отправить запрос POSTбез /api/issues/{projectname}обязательных полей, будет возвращена ошибка.{ error: 'required field(s) missing' }
Ожидание :5. Вы можете отправить GETзапрос на /api/issues/{projectname}получение массива всех вопросов по данному конкретному запросу projectname, содержащего все поля, присутствующие в каждом вопросе.
Ожидание :6. Вы можете отправить GETзапрос /api/issues/{projectname}и отфильтровать его, передав в качестве URL-запроса любое поле и значение (например, /api/issues/{project}?open=false). Вы можете передать одну или несколько пар поле/значение одновременно.
Ожидание :7. Вы можете отправить PUTзапрос /api/issues/{projectname}с идентификатором _idи одним или несколькими полями для обновления. В случае успеха updated_onполе должно быть обновлено, и в ответ должно быть возвращено значение {  result: 'successfully updated', '_id': _id }.
Ожидание :8. Если PUTотправленный запрос /api/issues/{projectname}не содержит _id, возвращаемое значение равно { error: 'missing _id' }.
Ожидание :9. Если PUTотправленный запрос /api/issues/{projectname}не содержит полей обновления, возвращаемое значение равно { error: 'no update field(s) sent', '_id': _id }. В случае любой другой ошибки возвращаемое значение равно { error: 'could not update', '_id': _id }.
Ожидание :10. Вы можете отправить DELETEзапрос /api/issues/{projectname}с идентификатором _idдля удаления задачи. Если идентификатор не _idотправлен, возвращается значение { error: 'missing _id' }. В случае успеха возвращается значение { result: 'successfully deleted', '_id': _id }. В случае неудачи возвращается значение { error: 'could not delete', '_id': _id }.
Ожидание :11. Все 14 функциональных тестов пройдены успешно и успешно.
